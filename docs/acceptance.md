# 验收记录

规范检查表不把本文当作全部条款已经通过。下面只记录这次实现实际验证过的内容。

| 编号 | 结果 |
| --- | --- |
| A01 | 账号与文档两个叶子模块，骨架和按需文件齐全，没有 Service 层。版本属于文档聚合，没有为了凑目录再拆模块。 |
| A02 | Controller 只绑定和输出。Resource 处理规则。Repository 执行数据库和事务。 |
| A03 | 公开业务方法使用 Request/Search 和 Response/PageResponse。认证接口 `Authenticate` 是平台会话契约，返回 Scope。 |
| A04 | 保存时先更新修订号再插入版本；版本插入失败的测试确认修订号和版本数都回滚。 |
| A05 | 没有跨模块强原子操作。保存和恢复的事务留在文档 Repository。 |
| A06 | 文档读写使用登录后的 ActorID。另一个用户访问同一 ID 得到不存在。 |
| A07 | 创建拒绝客户端主键。标题空值被拒绝。相同内容保存不新增版本。ID 使用字符串。 |
| A08 | 排序白名单、分页上限和标题转义已实现。搜索测试覆盖空结果和非法排序。 |
| A09 | 三份配置在 `configs/`。定位参数不从 YAML 读取。测试覆盖未知键、缺失 profile、`false` 环境变量覆盖。 |
| A10 | 只对 SQLite 做了迁移、外键、业务和备份测试。另外三库是计划支持。 |
| A11 | 集成测试覆盖未登录、分页形状、未知 API、页面回退、缺失静态文件、存活和就绪。 |
| A12 | 三个脚本入口已提供。发布包需要在有 PowerShell 的环境执行脚本生成，本次环境没有 pwsh，未实际打包三个平台。 |
| A13 | SQLite `VACUUM INTO` 往返测试已通过。没有做多版本升级回滚演练，也没有 systemd 实机安装。 |
| A14 | 没有引入缓存、队列、对象存储、多租户或 AI。 |
| A15 | 文档模块遵循商品样板的请求、仓储、事务和测试方式。没有另建无业务用途的商品模块。跨模块事务样板没有套用，因为保存和恢复是同一聚合。 |

验证命令：

```bash
go test ./...
cd web && npm test && npm run build
```

浏览器走查覆盖了注册、文稿加粗并保存版本、表格 `SUM` 显示 40、演示文稿编辑和新增幻灯片、重新打开后内容仍在，以及约 390 像素宽度下书案和文稿页没有横向溢出。
